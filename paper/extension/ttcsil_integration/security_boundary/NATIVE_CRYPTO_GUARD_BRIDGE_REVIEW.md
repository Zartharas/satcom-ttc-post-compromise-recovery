# Native CryptoLib → TTCSIL ingress-policy adapter preflight

**Research status:** F1 implementation feasibility only, not a canonical experiment, CCSDS conformance assessment, cipher proof, production adapter or NOS3/cFS run.

## Integration and trust flow

- Fresh disposable Ubuntu CI fetches **exact** upstream NASA CryptoLib `v1.5.2` commit `c216ede78b2f51b42838b13955602c0b481b53c2` and compiles its authenticating TC APIs. The original tested packet is a synthetic upstream test fixture, not a real spacecraft command.
- A separate OS process reads the protected TC frame generated by the existing native smoke, initializes CryptoLib, disables the clear-mode fixture and configures the operational authentication-enabled SA4 test fixture. `Crypto_TC_ProcessSecurity` must return `CRYPTO_LIB_SUCCESS`.
- The bridge reads decoded `TC_t.tc_header`, `TC_t.tc_sec_header.spi` and `TC_t.tc_sec_header.sh`, and looks up the selected Security Association in native CryptoLib. It supplies these to the original `ttcsil_guard_tc` C11 policy and checks a fixed **separately declared** expected tuple `(TFVN=0, SCID=3, VCID=0, MAP ID=0, SPI=4)`.
- A passing baseline requires authenticating CryptoLib processing plus matching selected SA and declared authorization. Negative controls include wrong expected/selected channel, clear authentication mode, absent cryptographic success, synthetic stale epoch and declared length smaller than header. Rejections must zero the returned payload length.
- The bridge does not create a key, control a spacecraft, change an upstream SA model, or transmit externally. All volatile output and packet bytes are removed from the isolated CI workdir.

## Explicit limitations

- The bridge uses `active_epoch=17` as a **test-only constant** on both sides because standalone CryptoLib's TC API does **not** provide the project-specific recovery epoch. The stale-epoch rejection is a unit-logic check, **not ground-space epoch verification**. F3 remains unimplemented.
- The selected SA pointer is acquired through CryptoLib's SPI-indexed interface after processing; this alone does not prove upstream enforces SA-to-GVCID binding. The added independently configured policy performs the comparison at the adapter boundary. An attacker able to modify that protected policy/SA store remains outside this preflight's assumptions.
- The test's `total`, `header=5` and allocated-buffer bounds are transfer-frame fixture values; they are **not** validated cFE Software Bus framing. The `CFE_SB_GetUserDataLength` underflow exposure is not patched by this project and the full cFS integration remains on security hold.
- The bridge currently does **not** provide independently authenticated return telemetry, a transaction journal, a power-loss test, a recovery COMMIT/CONFIRM restart, formal refinement or a separate cryptographic assessment.
- **Do not infer flight applicability, post-compromise security, runtime recovery progress, or increased publication impact from this native smoke.** Studies A–D and sibling projects are unchanged; no external research population is included.
